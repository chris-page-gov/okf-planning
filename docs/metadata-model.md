# OKF Planning metadata model

## Normative OKF v0.2 layer

The files under [`bundle/concepts/`](../bundle/concepts/) are the knowledge
concepts. Every non-reserved Markdown file has parseable YAML frontmatter and a
non-empty `type`. The root [`bundle/index.md`](../bundle/index.md) declares
`okf_version: "0.2"`.

Each planning concept uses the v0.2 provenance, trust and lifecycle fields:

| Field | Planning producer rule |
| --- | --- |
| `type` | Descriptive unregistered type such as `Planning Dataset`, `Planning Policy` or `Legal Instrument` |
| `resource` | Source record or landing page; never a constructed data endpoint |
| `sources` | One source-specific provenance record with a stable `id` |
| `generated` | Deterministic producer actor and frozen release timestamp |
| `verified` | Omitted because no human or process verification event is evidenced |
| `status` | `draft` |
| `stale_after` | Project-declared quarterly review boundary for the independent frozen snapshot; not an upstream freshness claim |
| `okf_explorer` | Preserved producer extension used by the Explorer projection |

Unknown fields and types are valid in OKF v0.2. Consumers must preserve them
when round-tripping and must not reject a concept because optional trust
families are absent.

## Additive semantic projection

[`okf-bundle.yamlld`](../bundle/okf-bundle.yamlld) and
[`okf-bundle.jsonld`](../bundle/okf-bundle.jsonld) map the catalogue to selected
DCAT 3 and PROV-O terms and publish a local context containing SKOS. These are
extension representations, not the OKF v0.2 core and not external
certifications.

| Extension field | RDF predicate |
| --- | --- |
| `identifier` | `dct:identifier` |
| `title` | `dct:title` |
| `description` | `dct:description` |
| `landingPage` | `dcat:landingPage` |
| `sourcePublisher` | `okf:sourcePublisher` |
| `bundlePublisher` | `okf:bundlePublisher` |
| `semanticAuthority` | `okf:semanticAuthority` |
| `wasAttributedTo` | `prov:wasAttributedTo` |
| `wasDerivedFrom` | `prov:wasDerivedFrom` |
| `wasGeneratedBy` | `prov:wasGeneratedBy` |

Organisations project to `prov:Agent`; policy, documents and legislation project
to `dcat:Resource`; dataset-like records project to `dcat:Dataset`.

## Explorer data plane

[`data/manifest.json`](../bundle/data/manifest.json) declares separate,
top-level array shards:

- `datasets` and the compatibility alias `records`;
- `resources`, keyed to a dataset through `dataset` and `dataset_route`;
- `publishers`, using stable route-safe identifiers;
- `relationships`, with `dataset/<id>` source and target routes.

Resources are only source URLs explicitly available to the producer. Curated
augmentations retain their actual publishers, including The National Archives,
Historic England, the Environment Agency, Natural England, the Planning
Inspectorate and HM Land Registry.

Relationships are generated by documented collection rules. Their
`evidence_type` is `deterministic-collection-rule` and their confidence is
`inferred`; no human review or entity reconciliation is claimed.

## Evaluation and integrity

The evaluation score is calculated from field presence and is labelled
`metadata-field-presence`. It does not measure statistical accuracy or fitness
for use. Semantic status values are `mapped-not-certified` or
`context-present-not-evaluated`.

The build deletes only its allowlisted generated paths, sorts source records,
tokens, filters and JSON keys, and checksums the exact generated output set.
Hand-authored `index.html`, `app.js` and `styles.css` remain outside generator
cleanup and the checksum scope.
